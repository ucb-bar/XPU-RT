# 03 — measuring both runtimes on the K1

**Needs the board.** Nothing on this page was run while this directory was written; every command
is quoted from the document named beside it.

What is measured and what is not: every callback (which hart, entry/exit `rdtime`), every camera
release, goal arrival and control output, and per-core busy % are **measured on the K1**. The flight
consequence of that timing is **simulated in Isaac Lab** ([`../04_fly/`](../04_fly/)). The drone
never leaves the simulator. Captions say it that way: *board-measured timing, simulated flight
consequence*. `docs/Baselines/ros_baseline_reproduction.md` opens with this.

**Never compile on the board while an arm is running** — a native build shows up in the sweep.
`scripts/board_campaign.sh` exists so that the whole sequence is serialised; `board_rate_sweep_x2.sh`
takes `results/codesign_feedback/board.lock`.

## The ROS 2 arms

```bash
scripts/ros_traced_matrix.sh <arm> [replicate]      # one arm across RATES, sampler around every run
RATES="25 30 36 38 40 45 60 75 90 120" scripts/ros_traced_matrix.sh vanilla4x2 1
scripts/board_rate_sweep_x2.sh                      # env RATES; both runtimes at every rate
scripts/board_ctrl50_arms.sh                        # the submitted figure's 50 Hz control timer
```

An arm is a real deployment named by what the launcher does to the process; the program never pins
anything itself and its manifest records the affinity mask and scheduling policy it ran under. The
arm table is in `docs/Baselines/ros_baseline_reproduction.md` §3 (what each arm's processes, executor, YOLO
width, control mode and placement are) and the measured result of every arm is in
`docs/Baselines/ros_arms_catalog.md` — 52 arms, 408 runs, generated by `scripts/ros_arms_catalog.py` from the
run manifests and the per-run roll-up. Regenerate it after running a new arm; do not edit it by hand.

Per run, in `/root/ros_mb/out/<tag>/` and pulled back to
`results/codesign_feedback/ros_traced/<hz>_<arm>_r<k>/`: `trace.csv` in the XPU-RT trace contract,
`released.csv`, `goals.csv`, `consumed.csv`, `ctrl_gaps.csv`, `manifest.json` and the sampler's
`cpu.csv`.

The arms the flight figures use are `vanilla4x2` (two perception instances, all eight cores) and
`vanilla_c50` (serial YOLO, 50 Hz control timer). `docs/Evaluation/showdown_rate_sweep_reproduction.md` §1 and
`docs/Evaluation/showdown_cam45_ros_out_of_box_reproduction.md` give the exact invocations for each.

## The XPU-RT arms

```bash
scripts/xpu_greedy_shard_at_rate.sh <hz>            # greedy on the board's per-width costs, 3 runs
LIMIT=5400 CPSAT_WORKERS=4 scripts/rate_feedback_loop.sh <hz>   # CP-SAT with two rounds of board feedback
scripts/board_stage2.sh <tag> <spec>                # clamp widths, feasibility check, 3 interleaved runs each
```

`xpu_greedy_shard_at_rate.sh` builds the arm's spec at the requested rate, solves it, makes it
buildable, checks it and executes it three times, writing
`xpurt_long/trace_w2pg<hz>r{1,2,3}_other_run1.csv`. `rate_feedback_loop.sh` is the two-round
co-design loop per camera rate; `docs/Artifact/artifact_checklist.md` §2 budgets it at board time plus about
three hours of CPU. `docs/Evaluation/figure_runbook.md` §3b item 2 names the specs and the certificate drivers.

Read a run with `scripts/xpurt_trace_report.py --windows …`.

## Pulling the results back and re-deriving the constants

```bash
scripts/pull_ros_traced.py                 # per-run chain.csv + summary.json, and ros_traced/summary.csv
.venv/bin/python scripts/measured_timing.py --verify    # every quoted constant re-derived from the raw files
```

`pull_ros_traced.py` builds each run's camera→goal and camera→control latencies from the raw stamps,
leaving blank cells where the depth-10 queue dropped a frame so that saturation is visible rather
than averaged away, applies a 3 s warm-up, and takes the per-core busy % over the run window.

`measured_timing.py --verify` needs no board and is in the no-hardware suite
([`../verify_no_hardware.sh`](../verify_no_hardware.sh)): it re-reads the committed traces and
recomputes every latency, control gap and late-frame count a figure prints, reporting DRIFT if a
recorded constant no longer follows from the data. It is the check that matters most.

Compare replicates on the *settled* window: at 45 Hz the camera period is shorter than one YOLO
callback, so the depth-10 queue fills and the latency rises to a fixed point, and the time to reach
it varies between replicates of the same arm. `docs/Baselines/ros_baseline_reproduction.md` §4 has the rule.

## The cadence traces the flights replay

```bash
.venv/bin/python scripts/ctrl_trace_from_board.py \
    results/codesign_feedback/ros_traced/36_vanilla4x2_r1/ctrl_gaps.csv \
    --out results/codesign_feedback/ctrl_traces/ros_vanilla4x236.csv
.venv/bin/python scripts/ctrl_trace_from_board.py \
    results/codesign_feedback/xpurt_long/trace_w2pg36r1_other_run1.csv \
    --out results/codesign_feedback/ctrl_traces/xpu_w2pg36.csv
```

One row per control output of one board run, looped by the simulator from warm-up to the run's end,
so the flight sees the runtime's measured cadence — bursts, gaps and all — rather than one number.
The XPU-RT source is a trace (one output per `mlp_control` instance); the ROS 2 source is
`ctrl_gaps.csv` (one output per control fire). These commands are
`docs/Evaluation/showdown_rate_sweep_reproduction.md` §2 verbatim.

Every trace has a `ReplayArm` in `scripts/figure_constants.py` whose latency is derived from a row of
`scripts/measured_timing.py`, so no figure types a number in. `tests/test_showdown_figures.py` asserts
that every trace on disk has one.

## What the board measurement does not establish

One board, one unit — nothing here separates silicon-to-silicon variation; the nodes run the
deployed three-network pipeline and a different graph shape distributes differently across an
executor; and the flight outcome is simulated. `docs/Baselines/ros_baseline_reproduction.md` §5 and §6 give
the scope of every claim and the limits, including the hand-pinned `p3` arm reaching a comparable
operating point on camera-to-control.

## Raw traces are archived, not committed

`results/codesign_feedback/ros_traced/*/trace.csv` and `xpurt_long/trace_*.csv` are 3–12 MB each and
re-measurable, so they are ignored and archived under
`results/codesign_feedback/archive_v3/board_traces_2026-09-17.tar` with their sha256 in that
directory's tracked `MANIFEST.sha256`. The per-run evidence that is *not* re-measurable
(`manifest.json`, `summary.json`, `ctrl_gaps.csv`, `kernel_sha256.txt`, `cpu.csv`) stays tracked. No
trace is tracked: the ones that were are in `archive_v3/board_traces_{ros_traced,xpurt_long}_2026-09-29.tar.gz`,
and `xpurt_long/stdout_*.txt` with them (`docs/Artifact/external_data.md`, "Raw traces").
